# Research: 과제 2 데이터 이해와 기준선

근거 데이터: InfluxDB `iot-bucket` 스냅샷(2025-08-01 ~ 2026-10-21 00:00Z, 2026-10-21 내려받음). CO₂ 1,788,391행, 온도 3,722,120행, 습도 3,722,072행.

## R1. 데이터 원천과 스냅샷

- **Decision**: InfluxDB에서 CO₂·온도·습도를 월 단위로 한 번 내려받아 `~/data/tsinfer/influx/<항목>.parquet`(원본 값은 문자열 그대로)으로 고정한다(`python -m tsdata.influx`). 이후 처리는 스냅샷만 읽는다.
- **Rationale**: InfluxDB는 계속 쌓이므로 다시 조회하면 결과가 바뀐다(재현성, 원칙 IV). 교육장 내부망이라 보드 B에서만 닿는다. 일부 시리즈의 값이 문자열이라(조회 시 "schema collision") 타입 변환은 정제 단계에서 한다.
- **Alternatives**: 매번 InfluxDB 조회(재현 불가), 과제 1 수집 DB만 사용(24시간이라 너무 짧음).

## R3. 분석 간격과 공간 대표값

- **Decision**: 분석 간격 **5분**. 센서별로 5분 평균을 낸 뒤, 공간마다 센서 값의 **중앙값**을 대표값으로 쓴다.
- **Rationale**:
  - 예측 거리가 5·15·30·60분이라 모두 5분의 배수다. 1분을 쓰면 회의실(10분)·EM500(2분)은 빈 칸이 대부분이고, 계산량도 5배다.
  - 5분 평균은 1분 센서의 측정 잡음을 줄인다. CO₂가 사람 수에 반응하는 데 몇 분이 걸리므로 5분이면 반응을 놓치지 않는다(추정, 진단 ④로 확인).
  - 실습실 CO₂ 센서는 4대이고 서로 200ppm 넘게 차이 난다. EM300-TH `1523`은 온도가 혼자 약 5℃ 낮다. 평균은 한 대에 끌려가지만 중앙값은 덜 흔들린다.
  - 센서 대수가 시각마다 바뀌면(한 대 결측) 중앙값이 계단처럼 뛸 수 있다. 진단서 해석에 적는다.
- **Alternatives**: 1분(빈 칸·계산량), 15분(5분 예측 불가), 공간 평균(이상 센서에 끌려감), 센서 하나만 대표로(그 센서가 빠지면 공간 전체가 빔).

## R4. 결측 처리 (2026-10-21 구현 중 수정, decisions R4)

- **Decision**: **센서별로** 5분 값의 빈 칸을 **마지막 값으로 최대 3칸(15분)까지 유지**하고, 그다음 공간 중앙값을 낸다. 공간의 모든 센서가 15분 넘게 비면 그 칸은 비워 둔다. 칸마다 `observed`(그 칸에 실제 관측이 한 건이라도 있음)를 둔다. **평가 정답은 observed 칸만** 쓴다.
- **처음 계획(버림)**: 공간 대표값 단위로 15분 이하 빈칸을 선형 보간.
- **바꾼 이유**:
  1. **누수**: 선형 보간은 빈칸 뒤의 다음 관측을 끌어온다. 그 값을 입력으로 쓰면 시각 t에 미래 값을 본 셈이다. 서비스에서는 다음 값을 모르므로 과거 값만 쓰는 채움이어야 학습·서비스가 같다(원칙 III).
  2. **톱니**: 공간 단위로 메우면 칸마다 값을 보낸 센서 구성이 달라진다(1·2·10분 간격 혼재). 센서 간 차이가 200ppm이라 대표값이 칸마다 뛰었다. 실제로 실습실 CO₂ 현재값 유지 오차가 5분 59.6 > 30분 37.2로 거꾸로 나왔다(30분은 10분 주기의 배수라 구성이 같아짐). 센서별로 먼저 채우자 5분 8.9 < 30분 35.6으로 정상이 됐다.
- **긴 공백의 처음 3칸도 채운다**: 그 시각에는 공백이 길어질지 알 수 없다. 서비스와 같은 계산이다.
- **Alternatives**: 공간 단위 선형 보간(누수·톱니), 보간 없음(회의실 입력 절반이 빔), 무제한 유지(몇 시간 전 값을 현재로 씀).

## R5. 기간 분할

- **Decision** (KST 날짜, 끝 날짜 포함): 학습 2025-09-01 ~ 2026-06-30(10개월), 검증 2026-07-01 ~ 2026-08-31(2개월), 시험 2026-09-01 ~ 2026-10-20(약 7주).
- **Rationale**: 시간 순서대로 나눈다(원칙 II). 시험을 가장 최근으로 둬 지금 운영 환경과 가깝게 한다. 학습에 2025-09~10이 있어 같은 계절을 한 번 본다. 검증은 과제 3 이후 모델 선택용이고, 2026-07 센서 고장(`2590`)이 검증 기간에 있다.
- **무작위로 섞으면 안 되는 이유**: 5분 간격 시계열은 이웃한 값이 거의 같다. 섞으면 시험 시점 바로 앞뒤의 값이 학습에 들어가 "미래를 보고 과거를 맞히는" 셈이 되어, 실제 운영(미래를 모름)보다 오차가 훨씬 작게 나온다.
- **Alternatives**: 시험 = 가장 오래된 기간(지금 환경과 멂), 매달 끝 주를 시험(경계마다 누수 위험, 구현 복잡).

## R6. 정규화

- **Decision**: 공간·항목별 평균·표준편차를 **학습 기간의 관측 칸만으로** 계산해 `prep_params.json`에 계산 기간과 함께 저장한다. 기준선은 정규화가 필요 없지만, 과제 3 이후 모델이 이 파일을 불러 쓴다.
- **Rationale**: AC-1, 원칙 II·III. 보간 칸을 빼는 이유는 지어낸 값이 분산을 줄이기 때문이다.

## R7. 기준선과 평가 시점

- **정의** (기준 시각 t, 예측 거리 h, 5분 격자):
  - 현재값 유지: ŷ(t+h) = y(t)
  - 최근 1시간 평균: ŷ(t+h) = mean(y(t−55분) … y(t)) — 12칸, 관측 칸이 절반(6칸) 이상일 때만
  - 어제 같은 시각: ŷ(t+h) = y(t+h−24시간)
- **입력 y**는 결측 처리한 공간 대표값(보간 포함)이다. 서비스에서도 같은 입력을 쓰기 때문이다.
- **평가 시점** (2026-10-21 구현 중 수정, decisions R7): t가 평가 기간 안이고, 정답 y(t+h)가 관측이며, 세 기준선이 모두 계산되는 시점. **기간·공간·항목·거리마다** 하나의 목록을 만들고, 같은 거리 안에서 세 기준선이 같은 시점을 쓴다(AC-2). 입력 y(t)는 관측이 아니어도 된다(서비스도 채운 값을 쓴다). 처음 계획(네 거리 공통, 입력도 관측)은 회의실에서 평가 시점이 3개뿐이라 버렸다. 목록은 `eval_points.parquet`로 저장한다.
- **지표**: MAE(평균 절대 오차, 단위 그대로: ppm, ℃). 과제 3 판정("60분 CO₂ 오차가 현재값 유지보다 30% 이상 작음")에 맞춘다.

## R8. 일정–CO₂ 반응 분석

- **상황**: 일정 자료(수업 시간표·회의실 예약)를 어디서 받는지 10/22 확인 대기.
- **Decision**: 그전에는 **평일 실습실 CO₂로 일과 시각을 추정**한다.
  1. 학습 기간 평일의 시간대별 중앙값 곡선에서 상승 시작, 점심 하락, 저녁 하락 시각을 찾는다 → "추정 일정".
  2. 날마다 "아침 기준값(05~07시 중앙값) + 100ppm을 처음 넘는 시각"(상승 시작)과 "저녁에 마지막으로 넘는 시각"(퇴실 반응)을 구한다.
  3. 반응 시간 = 상승 시작 − 추정 수업 시작. 추정 일정과 60분 넘게 어긋나거나 상승이 없는 평일을 "어긋난 날"로 나열한다(공휴일·휴강 후보).
- 일정 자료를 받으면 1단계만 실제 일정으로 바꿔 다시 돌린다(FR-012).
- **Alternatives**: 일정 자료가 올 때까지 미룸(진단서 미완성), 일정을 임의로 09:00~18:00로 가정(근거 없음).
