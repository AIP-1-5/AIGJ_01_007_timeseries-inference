# 과제 8에서 배운 것: 상시 추론 서비스

결과: [docs/reports/008-service/uptime.md](../reports/008-service/uptime.md), [result-format.md](../reports/008-service/result-format.md) · 코드: `service/`

## 무엇을 했나

매분 05초에 수집 DB의 최근 26시간을 읽는다. 학습과 같은 전처리를 거쳐 공간별 예측·이상·상태를 계산하고 MQTT(retained)와 조회 API로 내보내는 서비스를 systemd로 올렸다. 14시간 10분 동안 851주기를 하나도 빼먹지 않았다(AC-1). 10/22 09:07에는 서비스가 죽지 않고 **멈췄다**. `Restart=always`는 이 상황을 못 잡아서 systemd watchdog을 넣었다.

## 개념 → 왜 필요한가

| 개념 | 비유 | 정의 | 왜 필요한가 | 백엔드로 치면 |
|---|---|---|---|---|
| retained 메시지 | 게시판에 붙여 둔 공지 | 브로커가 토픽의 마지막 메시지를 보관했다가 새 구독자에게 바로 준다 | 대시보드가 나중에 붙어도 1분을 기다리지 않고 최신 상태를 본다 | 캐시에 저장된 최신 값 |
| 조회 API | 창구에 직접 물어보기 | `/spaces/lab` 같은 HTTP 요청으로 지금 결과를 받는다 | MQTT를 못 쓰는 시스템(LLM 도구, 웹)도 쓴다 | REST 컨트롤러 |
| 경보 중복 억제 | 화재경보가 1초마다 울리지 않게 | new → 30분마다 repeat → resolved | 매분 울리면 사람이 경보를 무시하게 된다 | 알림 디바운스, 멱등 이벤트 |
| fallback | 예비 발전기 | 모델 파일이 없거나 깨지면 현재값 유지·규칙으로 계속 돈다 | 일부가 고장 나도 서비스 전체가 멈추지 않는다 | Circuit breaker의 fallback |
| watchdog | 야간 경비원의 정시 무전 | 주기마다 "살아 있음"을 보내고, 5분간 안 오면 systemd가 죽이고 다시 띄운다 | 프로세스가 **멈추면** 죽은 게 아니라서 `Restart=always`가 반응하지 않는다 | liveness probe(쿠버네티스) |

## 알아둘 결과

- 주기 처리 시간: 평균 815ms, p95 914ms. 60초 중 1.4%만 쓴다. 대부분 DB 읽기와 전처리이고, 모델 계산은 아주 작다(과제 7).
- 모델 4개가 851주기 내내 `loaded`였다. 재부팅 직후 첫 주기만 4초였다(첫 로드).
- **"살아 있음"과 "일하고 있음"은 다르다.** 09:07~09:33에 프로세스는 살아 있었지만 주기를 하나도 못 돌았다.

## 짚어 둘 것 (롤백·동시성·인덱스·병목)

- **동시성**: 수집기가 쓰는 SQLite를 서비스가 읽기 전용으로 같이 읽는다. WAL 모드라 읽기가 쓰기를 막지 않는다. 결과는 메모리 한 벌을 lock으로 감싸 API 스레드와 주기 스레드가 같이 쓴다. 읽기 도중 반쯤 바뀐 값을 보지 않게 하려는 것이다.
- **인덱스**: 매분 "최근 26시간" 범위 조회를 한다. 기본키 `(센서, epoch, fCnt, 항목)`은 맨 앞이 센서라 시각 범위 조회에 못 쓴다. 과제 1에서 만든 `idx_readings_time(measured_at)`을 탄다(`EXPLAIN QUERY PLAN` → `SEARCH ... USING INDEX idx_readings_time`, 10/22 확인). 지금은 DB 전체(18.5시간치) 3만 8천 행을 107ms에 읽는다.
- **데이터가 늘면**: 수집 DB가 매일 커진다(18.5시간에 3만 8천 행 → 하루 약 5만 행). 인덱스로 26시간만 찾아 읽으므로 DB가 커져도 읽는 양은 그대로다. B-tree 탐색이라 찾는 비용만 log로 조금 는다. 인덱스가 없었다면 매분 DB 전체를 훑어 몇 주 뒤 주기 시간이 늘었을 것이다.
- **롤백**: 모델 파일을 바꾸면 다음 주기에 다시 읽는다. 잘못된 모델이면 fallback으로 계속 돈다. 예전 파일로 바꿔 놓으면 그게 롤백이다.

## 말로 설명할 수 있어야 할 것 3개

1. 막 시작된 5분 칸을 왜 안 쓰는지(학습과 서비스의 입력 분포를 같게).
2. `Restart=always`와 watchdog이 각각 무엇을 잡는지.
3. 수집기가 멈췄을 때 서비스가 그걸 어떻게 아는지(heartbeat 3분, 공간별 마지막 측정 시각).
