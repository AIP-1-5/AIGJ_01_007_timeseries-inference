# 과제 4에서 배운 것: 이상 탐지

결과: [docs/reports/004-anomaly](../reports/004-anomaly/README.md) · 코드: `tsmodel/anomaly.py`

## 무엇을 했나

정상 데이터만으로 오토인코더를 학습하고, 규칙 5개를 만들어, 실데이터에 직접 심은 고장 60건으로 평가했다. 탐지율 80%(통과), 헛경보 하루 1.36회(미통과).

## 개념 → 왜 필요한가

| 개념 | 비유 | 정의 | 왜 필요한가 | 백엔드로 치면 |
|---|---|---|---|---|
| 오토인코더 | 그림을 요약했다가 다시 그려 보기 | 입력을 작게 압축했다가 복원하도록 배운 모델. 복원이 안 되면 "처음 보는 모양" | 현장에는 고장 정답이 거의 없어 정상만 보고 배워야 한다 | 정상 트래픽 패턴 학습 기반 이상 감지 |
| 임계값 | 화재 경보기 감도 | 점수가 이 값을 넘으면 경보 | 낮추면 더 잡지만 헛경보가 는다(교환 관계) | 알림 임계치(p99 응답 시간) |
| 이벤트 단위 평가 | 사건 몇 건 중 몇 건을 잡았나 | 칸 단위가 아니라 고장 구간 단위로 탐지율·지연·헛경보를 셈 | 운영자는 "몇 번 울렸나"로 체감한다 | 인시던트 단위 MTTD |
| 고장 심기 | 소방 훈련 | 정상 데이터에 알려진 모양의 고장을 넣어 정답을 만듦 | 정답 없는 실데이터에서 탐지기를 잴 방법 | 카오스 엔지니어링 |
| 경보 묶음(억제) | 같은 화재에 벨을 한 번만 | 30분 안의 경보는 한 건으로 | 같은 고장에 매분 울리면 알림을 끈다 | 알림 dedup·그룹핑 |

## 내가 알아둘 결과

- 오토인코더는 **정상 범위 안의 고장**(값 고정, 서서히 오르는 영점·온도)을 못 잡는다. 규칙이 그 자리를 메웠다.
- 헛경보는 전부 규칙에서 나왔다. 실데이터의 드문 날(늦은 퇴실, 휴일 사용)까지 헛경보로 셌기 때문이다.
- 처음엔 "창 평균 오차"를 점수로 써서 튄 값 한 칸이 묻혔다 → "창 안 최대 오차"로 바꿈. **집계 방식이 무엇을 볼 수 있는지 결정한다.**

## 말로 설명할 수 있어야 할 것 3개

1. 오토인코더가 값 고정을 못 잡는 이유와, 규칙이 그걸 잡는 방식.
2. 임계값을 낮출 때 탐지율·헛경보가 어떻게 같이 움직이는지(표로).
3. 정답 없는 실데이터에서 탐지기를 검증하는 방법(고장 심기 + 사람 확인 기록).

## 스스로 확인할 질문 2개

1. 공간별로 임계값을 다르게 두면 헛경보 1.36회를 1회 아래로 내릴 수 있을까?
2. 과제 3의 예측 오차를 이상 점수로 쓰면 냉방·환기 정지를 더 일찍 잡을 수 있을까?
