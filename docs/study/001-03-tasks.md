# 학습 노트: 과제 1 tasks (데이터 수집 체계)

날짜: 2026-10-21 · 문서: [tasks.md](../../specs/001-data-collection/tasks.md)

## 무엇을 했나

- plan을 작업 44개(T001~T044)로 쪼갰다. Setup → Foundational(설정·파서·epoch·저장소) → US1~US4 → 마무리 순서.
- 각 구현 작업 앞에 테스트 작업을 두었다(예: T008 파서 테스트 → T009 파서 구현).
- 구현 직전(2026-10-21)에 범위를 조정했다: 장애 시험 보조 스크립트(T026·T027)는 빼고, sudo가 필요한 작업(T028~T030)은 **[사용자]** 표시로 바꿨다.

## 왜 이렇게 했나

- Foundational을 먼저 둔 이유: 모든 스토리가 같은 설정·파서·저장소를 쓴다. 이게 흔들리면 스토리마다 고쳐야 한다.
- US2(서비스 등록)를 US1 바로 뒤에 둔 이유: AC-3은 "연속 24시간"이 필요하다. 서비스를 빨리 켜야 24시간 시계가 돈다.
- 장애 시험을 사용자 실행으로 돌린 이유: 보드 B를 팀원도 쓴다(팀원 수집기 2개가 이미 돌고 있음). iptables·mosquitto·재부팅은 남에게 영향을 준다.

## 말로 설명할 수 있어야 할 것 3개

1. 왜 테스트를 구현보다 먼저 쓰는가 (기대 동작을 먼저 숫자로 못 박으면, 구현이 맞는지 기계가 판정한다).
2. [P] 표시의 뜻 (다른 파일을 다루고 서로 기다리지 않아 동시에 할 수 있음).
3. 24시간 측정 구간 안에서 장애 시험을 하면 무엇이 문제인가 (시험으로 생긴 결측이 커버율을 깎는다 → 구간 밖에서 하거나 "의도한 중단"으로 표시).

## 스스로 확인할 질문 2개

1. US3(현황·보고서)를 US2보다 먼저 하면 일정에 어떤 영향이 있는가?
2. T028(서비스 설치)이 끝나기 전에 T035(24시간 보고서)를 시작할 수 있는가? 왜?
